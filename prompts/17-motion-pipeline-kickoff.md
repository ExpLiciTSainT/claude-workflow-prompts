# The motion kickoff (paste into the director window for a new character's motion)

Use for: the one message that starts a character's movement set (or, with its last line, the fighting motions) in the director window, after the "Two windows" preset; the director then runs every step in order so none is found late.
Why: the male's round found its recording route, room, camera, stance method, image quota and review shape one phase at a time; each is now a step with its guard before it (Torvane Docs/process/humanoid-fighter-motion-pipeline.md, HU-130 and HU-131).

```text
MOTION KICKOFF. Character: <character name>. Review folder: <review folder>. Keys file: <keys file path>. Reference folder: <folder with my pictures and videos of how he stands and moves>. My words: <what I want, in my words>.

Director, before the first "run", in this order:
1. Create <project> (block 16) and append my words to REQUEST.md verbatim. Read the pipeline doc (HU-130, HU-131) and the repeat-mistakes rows it names; every phase below is one of its steps and carries that step's guard in its brief.
2. PLAN.md from the full inventory of the finished set: every move, its keys from the keys file (a key the game does not bind yet is named now), every consumer of the stance and the carriage. Every time I named in a reviewed video is written with the move from that video's index; every numeric bar with its derivation.
3. The stance reference: a stand on a realistic human made from my words, the image tool's quota and its fallback named before step 1, the generator looking at every image, Grok never asked for images of the bare character; the sheet to my review folder. My pick is the go: the character is then posed to it in the visible window (never by words or pose transfer), shown to me later as engine stills.
4. The plan: a fresh planner lane, round 1 on the plan and round 2 on the method, each round run by the driver (AGY by the agy command, Grok, an Opus adversarial); the planner answers every finding; you rule the disputes.
5. The recording route before any recording: only the keys, the mouse and the start place set by the route; both soles and the floor under them in frame by the game's own camera; the room in the game's own data, which my launcher reads; rebuild before record; the record line complete (build, AGY's read and verdict, the bar values); frame pacing measured; DINO, then AGY's standing items calibrated; a test recording that runs every bar live.
6. Then in order: the stands as engine stills in the map from every view (my yes); the living idle; the carriage still (my yes); the carriage layer; the shared fixes with magnitude bars passing on live recordings; one video per motion in my review folder (my verdict on each); the checkpoint.
Nothing I did not ask for starts without my yes. Report what is done and what is next, never a date.

FIGHTING MOTIONS (paste this paragraph instead of the first line when the movement set is locked): character <character name>; weapon <weapon> held <in one hand | in both hands | both>; attacks, blocks, feints, dodges and jumps as the keys file binds them; my reference for each attack kind in <reference folder>; the locked movement set is <movement checkpoint packet path>. Run HU-145's rows on the same steps (the guard per hold as a human sheet and engine stills, the swing still per attack kind, the blade and both hands in frame on every recording) and reuse every other step unchanged.
```
